# DuckDuckRun 第 2 阶段工程加固报告

> **历史证据。** 本文只对应标题所示阶段及当时提交，不是 2026-09-02 remediation 候选的发布放行依据；当前状态见 MANUS_CONTEXT.md 与 docs/qa/release-candidate-report.md。

> **结论：本地工程门禁已绿色；不得发布。** 本阶段按 ADR-001 的“保留并修复”路线关闭本地 A-01 浏览器回归，建立可复放随机局、可销毁运行时、版本化静态制品和最小 CI。GitHub Pages 线上制品仍是旧版本，且没有执行部署；A-02 因此保持 **P1 发布阻断**。移动性能数据仅来自 Chromium 触摸/DPR 模拟，未达到 45 FPS 目标，也不能替代 Android 真机结论，A-04/A-09 仍为发布阻断。

## 1. 范围与基线

本阶段只处理审查编号 A-01 至 A-09 所需的 P1 和基础性 P2；没有更换 Canvas/ESM 架构、引擎或依赖版本，也没有增加关卡、账号、后端、广告、排行榜、PWA 或大规模美术。起点为 `5a8631be20eb0d3d3c257636fe526d1f646c747f`；该提交相对上一阶段记录的游戏代码基线 `b90462e1c182fc0fee5ee1fe29c9b6789690d9a9` 仅包含审查与承接文档。[1] [2]

## 2. 实施内容

运行时入口现在只允许一次 `startApp()`；`disposeApp()` 会取消帧循环与预取、移除窗口监听器、销毁输入控制器、停止 BGM 并关闭 Web Audio 上下文。输入层将键盘、鼠标和触控注册收敛为同一控制器，建立的每个监听器都有对应的释放路径。音频上下文只能在真实键盘或指针手势中创建/恢复；静音依旧可用，后台会暂停，销毁时不会留下 BGM 定时器或节点。[3] [4] [5]

可复放模式通过 `?demo&seed=20260901` 或任意整数 `?seed=<整数>` 启动。游戏逻辑的随机数全部流经核心随机源，`startRun()` 在设置了 seed 时重置该源；视觉相机抖动和 Web Audio 噪声仍使用独立随机源，因此帧率与音频状态不会改变障碍、掉落和路线序列。浏览器测试验证同一 seed 的两次开局得到一致的首个障碍簇。[3] [6]

静态构建不引入打包器或运行时依赖。`npm run build` 复制现有静态文件至 `dist/releases/<build-id>/`，向制品 HTML 注入构建 ID，输出 `build-info.json` 文件清单，并生成仅作版本跳转的根入口。`test:dist` 在临时静态服务器上验证制品入口和清单文件全为非 4xx/5xx；`test:size` 对首屏和全会话制品做 gzip 预算门禁。[7] [8] [9]

## 3. 前后测量

所有数据均在本地 Chromium 无头自动化中采集；网络条件为 CDP 蜂窝 4G 模拟（150 ms 延迟、500 KB/s 下行、125 KB/s 上行），固定输入种子为 `20260901`。移动列是 844×390、DPR 2、触摸模拟，**不是物理 Android 真机**。内存是 Chromium CDP 在预热一次开局后、强制 GC 前后的 JavaScript 堆变化，只用于检测连续重开的回归信号，不代表整机内存或 GPU 纹理内存。

| 指标 | 加固前 | 加固后 | 目标/门槛 | 判定 |
|---|---:|---:|---:|---|
| 桌面首个可玩菜单 | 1,714 ms | 1,674 ms | ≤4,000 ms；硬上限 8,000 ms | 通过 |
| 移动模拟首个可玩菜单 | 1,497 ms | 1,519 ms | ≤4,000 ms；硬上限 8,000 ms | 通过 |
| 首屏传输（桌面/移动模拟） | 252,575 B | 257,636 B | ≤6 MiB | 通过 |
| 完整首次会话传输 | 1,431,858 B | 1,437,219 B | ≤20 MiB | 通过 |
| 桌面模拟平均帧率 | 37.99 FPS | 38.86 FPS | 60 FPS | **未达到；自动化信号，不作为真机结论** |
| 移动模拟平均帧率 | 40.68 FPS | 40.23 FPS | ≥45 FPS | **未达到；发布阻断待真机归因** |
| 桌面 1% low（自动化） | 29.85 FPS | 29.94 FPS | ≥30 FPS | 接近但未达到；需真机复测 |
| 移动 1% low（自动化） | 29.94 FPS | 29.94 FPS | ≥30 FPS | 接近但未达到；需真机复测 |
| 桌面预热后连续重开 10 局 JS 堆变化 | +7.11% | +7.11% | ≤15% | 通过 |
| 移动模拟预热后连续重开 10 局 JS 堆变化 | +7.13% | +7.19% | ≤15% | 通过 |
| 控制台错误/网络失败 | 0 / 0 | 0 / 0 | 0 / 0 | 通过 |
| 运行时外部请求域名 | 0 | 0 | 关键资源不得依赖境外 CDN | 通过 |

加固前后首屏和会话传输存在约 5 KB 的测量波动，来自浏览器资源计时与加载顺序；两者均远低于预算，不能据此宣称有实际包体膨胀。生产构建 gzip 体积门禁更稳定：首屏 480.5 KiB、全会话 5.50 MiB，分别低于 6 MiB 与 20 MiB。[9]

> **性能发布判断：不通过。** 虽然弱网启动、资源预算、错误数和连续重开堆增长达标，移动模拟平均帧率为 40.23 FPS，未达到 45 FPS 的默认目标。无头 Chromium 的帧率也不能代表物理设备；在获得 Android 中端/低端、iPhone Safari 和两种微信 WebView 的 S1–S8 记录前，不能发布或宣传移动兼容性。[10]

## 6. 回滚与下一阶段前提

本阶段所有运行时、测试和工作流修改均可通过回退至阶段起点 `5a8631be20eb0d3d3c257636fe526d1f646c747f` 撤销。未修改默认分支，未创建 PR，未部署，也没有生成需要清理的线上资源。下一阶段应优先取得设备矩阵的 P0 实机样本和真实缓存切换证据；若移动真机确认性能不足，再针对证据做最小渲染裁剪，不得预先更换引擎或重写状态机。[1] [10]

# DuckDuckRun 设备与浏览器验收矩阵

> 本矩阵区分**已实测**、**自动化模拟**与**待实机验证**。视口模拟不能替代型号、GPU、温控、电池和嵌入容器验证；未测试的单元格不得在对外材料中标记为“兼容”。

## 验收场景定义

| 编号 | 场景 | 最小通过条件 |
|---|---|---|
| S1 | 冷启动与首帧 | 3 秒内可见菜单；无 console error、4xx/5xx 或未处理异常 |
| S2 | 教程与首次成功 | 菜单→选关→第一关；四步教程完成并进入正式跑局 |
| S3 | 输入 | 键盘四方向、触摸点击和四方向滑动的语义准确；不误触 UI |
| S4 | 失败/重开 | 自然失败可读；Enter/触摸主 CTA 可重开；十次循环无白屏/显性异常 |
| S5 | 生命周期 | P 暂停/继续；失焦或切后台暂停音频与游戏，返回后可继续 |
| S6 | 性能与热 | 10 分钟跑局；FPS P95、长任务、内存、温升/耗电纳入设备日志 |
| S7 | 网络与缓存 | 首次冷载、弱网、离线恢复、版本切换；无新旧模块混用 |
| S8 | 分享与容器 | 微信菜单/分享、Web Audio 解锁、复制链接、iOS Safari 兼容 |

## 下一阶段的最小实机样本

| 优先级 | 设备/容器 | 原因 | 所需数据 |
|---|---|---|---|
| P0 | Android 低端机 + 微信 | 最大的 DPR、性能、WebView 与后台压力组合 | 冷启动、10 分钟跑局、温升/耗电、长任务、失败率、后台恢复 |
| P0 | iPhone + 微信 | iOS 音频手势、Safari/WebView 缓存与分享差异 | S1–S8 完整录像/屏幕记录、控制台远程日志（可得时） |
| P1 | iPhone Safari | 纯 Safari 与微信容器隔离问题 | S1–S7、横竖屏、音频恢复 |
| P1 | Android Chrome | 将 WebView 问题与浏览器问题区分 | S1–S7、低网速和缓存切换 |
| P2 | Windows Edge、macOS Safari | 保证桌面键盘与字体回退一致 | S1–S5、截图比对 |

## 发布门槛

在移动端公开发布前，Android 微信、iPhone 微信、iPhone Safari 和 Android Chrome 四个单元格中，S1–S5 与 S8 必须通过；S6/S7 要有记录且不存在 P1/P0。若某平台不支持，将其明确排除在传播渠道和文案之外，而不是依赖“理论上应可运行”。线上发布前还须满足 `npm test` 全绿、当前制品 SHA 与线上版本匹配、缓存切换演练成功。这个门槛直接承接 A-01、A-02、A-04、A-06 和 A-09 [2]。

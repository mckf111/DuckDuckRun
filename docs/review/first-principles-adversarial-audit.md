## 一、第一性原理判断

玩家价值不是“有多少模块”，而是玩家在第一次横屏触摸后能否看懂、成功一次、失败后愿意再跑，并在十分钟后仍获得新鲜且可复盘的反馈。该项目已经具备可识别的白鸭角色、城市地标、四步动作教学、收集与关卡系统；它的问题不是缺少功能，而是**可发布性不可验证**。因此，重写会丢弃已验证的状态机、内容资产和测试资产，却不能天然解决发布、设备兼容和资产台账问题。

南京元素并非纯装饰：中华门、鸡鸣寺、中山陵、秦淮、紫金山、南京长江大桥等均进入 `LEVELS`/风物配置和图鉴/掉落循环，而不只出现在菜单背景中 [2]。但其文化准确性的上限受资产溯源和替代图说明约束。例如授权页已将金箔、云锦、雨花茶等说明为“工艺示意或相关实景”，这是诚实的产品处理，却也意味着不能把“城市题材”误宣传为严谨的数字导览 [3]。

| `npm run lint` | 失败 | 未定义 `lint` | E-01 |
| `npm run test:syntax` | 通过 | 21 个运行时模块语法检查通过 | E-01 |
| `npm run test:logic` | 通过 | 7 个规则/节奏/可生还路径子测试通过；最长约 25.7 s | E-01 |
| `npm run test:save` | 通过 | 3 个存档迁移与 I/O 子测试通过 | E-01 |

现有 CI 在 Chromium 上安装运行时，但浏览器脚本对启动目标的选择与 CI 安装策略存在不一致风险；更直接的事实是最新远端工作流同样在该断言失败，预览 job 因依赖测试而不执行 [4]。这不是“测试太严格”的借口：要么预取行为真的回归，要么断言与设计契约漂移；两种情况都必须先由下一阶段判定并修复。

### 2.2 三类视口与关键操作

| 环境 | 实际操作 | 结果 | 运行时与网络结果 |
|---|---|---|---|
| 1440×900 桌面，DPR 1 | 菜单→选关→第一关→四步教程→自然失败→Enter 重开→P 暂停/继续→`blur` 自动暂停 | 全部可达；教程完成时 `tutorial:null`，随后进入正式第一关 | 无控制台 error/warning、请求失败或 4xx/5xx；主机仅本地 [E-03] |
| 844×390 横屏触屏，DPR 2 | 触摸菜单→选关→第一关；CDP 真实触摸右滑 | 菜单/选关可点击，车道由 0 变为 1 | 无控制台/网络错误；首会话约 1.26 MB（含脚本 253 KB、图片 695 KB、字体 308 KB）[E-03] |
| 390×844 竖屏触屏，DPR 2 | 检查旋转层；在遮罩下触摸“开始冒险”；切到横屏 | 旋转层为 `flex`，遮罩下点击不改变菜单状态；横屏后遮罩消失 | 未发现请求错误；但用户必须旋转设备 [E-03] |

失败页主 CTA “起来再跑（Enter）”显著，死因、距离和鸭蛋可辨。桌面教程、失败、横屏菜单、竖屏遮罩和线上菜单截图均已保存为会话证据，索引见 [`evidence-index.md`](./evidence-index.md)。图形层面已达到可公开试玩水准；就高龄人群而言，横屏小字、强制横屏和全 Canvas 交互仍是实质门槛。

### 2.3 生命周期、性能与外部依赖

项目在真实键盘/触摸输入下验证了暂停、继续、失焦暂停和十次失败→Enter 重开循环；十次循环没有控制台错误、白屏或网络失败，且开局对象数未呈上局残留累积 [E-04]。但是当前 Chromium 的性能指标接口未暴露 JS 堆/事件监听器数，**不能据此宣称不存在内存泄漏**。

自动化浏览器的帧间隔不是物理真机帧率，不能据此承诺手机 60 FPS。其作为风险信号仍有效：桌面平均约 30.97 ms、横屏 DPR 2 平均约 29.58 ms；横屏会话记录到 116、93、147、95 ms 的长任务 [E-03]。这与项目期望的低端机性能目标存在张力，应由真机采样裁决。运行时资源在本地均来自同源；线上旧版本的请求主机也仅为 `mckf111.github.io`，未发现境外第三方运行时资源、CORS 错误或 Service Worker [E-03]。

音频采用懒创建的 Web Audio：首次画布指针操作创建/恢复 AudioContext，失焦路径会暂停音频 [5]。真实触摸会话中上下文达到 `running`，冷启动桌面并未自动创建音频上下文；在本审查环境中没有复现自动播放策略阻断。实际微信 WebView、iOS Safari 和 Android 低端机尚未用物理设备验证，因此不得把该结果外推为兼容性承诺。

## 四、发布判定与阶段 2 边界

当前结论是**禁止按“最新版本已上线”进行推广**，但不构成重写理由。阶段 2 获准处理 A-01、A-02、A-03、A-04、A-05、A-06、A-07、A-08、A-09 的最小改动，并须先补齐设备和发布验收。阶段 2 不得做以下事项：不新增关卡、道具、商业化、账户、服务端、重型框架、物理引擎、PWA 离线系统或大规模美术重绘；不以升级依赖来“修好”测试；不在 P1 关闭前部署。

重写阈值未达到。现有基础设施的局部修复预估为 **11–19 人日**，主要是门禁、发布、可访问性/性能测量和台账；从零重建同等功能、十关内容、存档迁移、触摸输入、音频、素材页及测试至少 **30–45 人日**，且会引入重新验证的风险。局部修复约为重建成本的 25%–63%；只有当下一阶段证明运行时架构无法隔离 P1/P2 或最小修复稳定超过约 18 人日时，才重新讨论“提出重建”。详细决策见 [ADR-001](../architecture/ADR-001-target-architecture.md)。
